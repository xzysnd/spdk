详细说明

1. QEMU / KVM 与 SPDK 的关系

KVM 是 Linux 内核的虚拟化模块，负责 CPU 和内存虚拟化。QEMU 是用户态进程，模拟硬件设备。SPDK 是用户态存储框架，通过 vhost-user 协议为 QEMU/Guest VM 提供后端存储。

IO 路径：Guest VM 发出 IO → QEMU virtio 设备 → vhost-user 协议 → SPDK bdev → DPDK → NVMe 硬件。

SPDK 的角色：SPDK 替代了 QEMU 内部的存储后端（如 -drive file=），用用户态 + 零拷贝实现高性能 IO。QEMU 只负责模拟 virtio 硬件前端，IO 实际处理在 SPDK 进程中完成。

2. 热替换与子系统的关系

SPDK 由多个子系统组成（iobuf → accel → bdev → vhost），每个子系统在热替换中扮演不同角色：

  • iobuf：IO 缓冲池。Secondary 必须先初始化（拓扑序第 1），因为后续子系统依赖它分配 IO buffer。
  • accel：加速框架（加密/压缩/CRC 等）。Secondary 第 2 初始化，因为 bdev_register 会解引用 g_modules_opc[opcode].module，如果 accel 未初始化则崩溃。
  • bdev：块设备层。Secondary 第 3 初始化：调用 spdk_bdev_initialize 创建基础设施（mempool/zero buffer），然后通过 secondary_reconstruct 回调重建每个 bdev。
  • vhost_blk：vhost 后端。Secondary 第 4 初始化：重建 vhost 设备结构。第 5 步 takeover：接收 Primary 传递的 Guest 内存 FD，恢复 QEMU 连接。

关键点：子系统按拓扑顺序初始化（subsystem_sort()），保证依赖关系。Primary 运行时 Secondary 并行完成 pre_init，之后只需 primary_exit → secondary_init（takeover）即可切换，IO 中断 < 200ms。

3. 热替换对 QEMU/KVM 的影响

对 KVM：完全透明。KVM 只管 CPU/内存虚拟化，不涉及 SPDK 进程切换。

对 QEMU：几乎透明。QEMU 通过 vhost-user Unix socket 连接 SPDK，热替换时：

  • FD 迁移：Primary 通过 SCM_RIGHTS 将 Guest 内存 FD 传给 Secondary
  • 连接状态：vhost 的 QP/VRING 状态在共享内存中，Secondary 直接继承
  • QEMU 感知的只有短暂的 IO 停顿（< 200ms），然后 IO 自动恢复

当前限制：vhost 设备重建用 ctxt=NULL，vhost-user 会话（QEMU 的连接）不自动迁移 — Phase 13b 将完善。

4. DPDK 多进程机制

热替换的底层基石是 DPDK 多进程：

  • Primary 和 Secondary 共享同一 hugepage 内存（通过 --shm-id 连接）
  • 使用相同 --base-virtaddr 保证虚拟地址一致，bdev 指针跨进程有效
  • Primary 不退出、不销毁 EAL，Secondary 直接接管共享内存中的数据结构
  • 这比传统的"停旧进程 → 启新进程"方案快 10 倍以上（3-5s → <200ms）
